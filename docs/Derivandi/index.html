Derivandi

Derivandi can analyse amd generate Source code at compile time. It is based on Annotation Processing, also called Annotation Processing Tool (APT).

Key Features

  • nulls save

  • One Data Structure instead of two partially overlapping ones

  • Types for Leafs of the abstract syntax tree, like Class, Enum or Method

  • Java Source File DSL for easy generation

  • Java Beans Support

  • Generation of typesafe Annotation Representations

  • Adapters for interoperability with APT

  • Reduces Boilerplate needed to work with APT. Processors have ~20% less LOC

  • dependency free

Introductions

Depending on your background, there are different introductions:

  • From ordinary Java to generated code

  • From runtime reflection to compile-time safety

  • From annotation processing to simpler code generation

Setup

Dependency

<dependencies>
	<dependency>
		<groupId>com.derivandi</groupId>
		<artifactId>derivandi</artifactId>
		<version>1.0.0-SNAPSHOT</version>
	</dependency>
</dependencies>

<build>
	<plugins>
		<plugin>
			<groupId>org.apache.maven.plugins</groupId>
			<artifactId>maven-compiler-plugin</artifactId>
			<version>${maven-compiler-plugin.version}</version>
			<configuration>
				<annotationProcessorPaths>
					<path>
						<groupId>com.derivandi</groupId>
						<artifactId>derivandi</artifactId>
						<version>1.0.0-SNAPSHOT</version>
					</path>
				</annotationProcessorPaths>
			</configuration>
		</plugin>
	</plugins>
</build>

Register the Processor

Processors can be used on the classpath or modulepath. To make then discoverable they need to be registered for each path type.

Without Java Modules

Create a File at src/main/resources/META-INF/services/ called javax.annotation.processing.Processor. And add all qualified names of your processors with one per line. In this case org.example.MyProcessor.

With Java Modules

add provides javax.annotation.processing.Processor with org.example.MyProcessor; to your module-info.java

When to use compile time meta-programming?

  • The feedback cycle is as fast as possible. If generated sources are invalid the compiler will tell you

  • It’s harder to make mistakes, as the compiler validates everything

  • Meta Programming is always complex irrespective of the technology or api. Limiting it to compile time:

    • Enforces separation of concerns with a hard boundary for architecture erosion

    • Reasoning about an Annotation Processors impact on runtime is limited to the generated files and can therefore be drastically simpler

  • No lock-in - generated sources can be added to the source tree and the generator removed

When not to use compile time meta-programming?

  • Annotation Processors are limited to compile time, if you need Meta Programming at runtime and generating behavioral patterns like Strategy is not enough

  • Knowledge about the reflection is very common. Adding a new Technology increases the maintenance burden at least temporally
